# ADR-009: Paid TierのAI予算を全体推定額で管理し、上限時は外部AIを停止する

Status: Accepted

関連: [#637 Issue #120-1](https://github.com/yama180sx/receipt-ai-app/issues/637)

## 背景

Gemini APIの請求・利用Tier・クォータはGoogleプロジェクト単位で扱われる。RecAIptの
`FamilyGroup` 単位で集計済みのOCR利用量だけでは、プロジェクト全体の支出上限を
管理できない。商品分類AIの利用量も別ログに記録されている。

Google Cloud Billing Budgetは請求額を監視して通知できるが、アプリケーションの
外部AI呼出しを同期的に停止する仕組みではない。また、請求情報・プログラム通知には
遅延がある。このため、Google側の予算管理とアプリ側の防御を併用する必要がある。

## 決定

### 管理単位と金額の意味

- 予算設定、停止状態、変更監査はFamilyGroupに属さないアプリケーション全体の単一データとして持つ。
- 停止判定には、`ApiUsageLog`（OCR）と`ProductClassificationAiRun`（商品分類AI）を
  全世帯横断で合算した**アプリ内推定額**を使う。
- アプリ内推定額はGoogleの請求額ではない。単価履歴、集計遅延、Google請求側の丸め・
  割引・税などによる差異があり、厳密な請求上限の保証には用いない。
- Google Cloud Billing Budgetは請求管理者への外部監視として別途設定する。アプリから
  Google Billingの予算を変更・停止制御しない。
- アプリ内の月額予算期間はGoogle Cloud Budgetと同じ、米国・カナダ太平洋時間の毎月1日0:00を
  開始・リセット時刻とする。夏時間中は日本時間16:00、冬時間中は17:00である。

### しきい値と通知

- 初期しきい値は月額予算に対して50%・80%・100%とする。実際の金額と各しきい値は
  管理者が変更できる。
- 50%・80%は通知のみでAI処理を継続し、100%で新規OCRと商品分類AIを停止する。
- 通知先はDiscord（既定）とメールの複数選択とする。選択されていない方式へは送信しない。
  予算停止機能を有効にするには、Discordまたはメールを少なくとも1つ選択することを必須とする。
- 同一月・同一しきい値・同一通知先について重複通知しない。配送失敗は安全な運用ログと
  監査に残し、Webhook URL・SMTP資格情報・予算の機微情報はログへ出さない。配送は最大3回まで
  指数バックオフで再試行するが、配送の成否をGemini利用の停止・再開判定には使わない。

### 停止・再開

- Geminiへの外部呼出しの直前に、全体予算状態を判定する。
- 停止中はOCRと商品分類AIのGemini APIを呼ばない。OCRは安全な固定エラーコードで失敗台帳へ
  記録し、商品分類AIは保存済みレシートを失敗させず、明細を`needs_review`のまま残す。
- 複数Workerの同時呼出しで停止しきい値を超えないよう、Gemini呼出し前にモデル・用途別の想定最大額を
  DBトランザクションで予約する。判定には確定利用額と未精算予約額を合算し、応答後は実トークン額へ
  精算する。失敗時は予約を解放する。
- 単価改定にはモデル・用途別の最大入力・最大出力トークンを持たせる。予約額は1回の呼出しではなく、
  OCRの通信リトライと算術不整合時の自己修復再解析まで含むジョブ全体の最大額で計算する。
- Geminiの各HTTP試行には2分の上限を設ける。既存の最大3回リトライを含め、予約の有効期限は15分とし、
  1分ごとに期限切れ予約を回収する。回収した予約の元ジョブは自動再実行せず、既存方針どおり利用者の
  明示的な再実行だけを許可する。
- 集計値や停止状態を取得できない障害時も、外部AI呼出しは停止する（フェイルクローズ）。
- 手動レシート登録、既存レシートの閲覧、既に得た解析結果の確定保存は停止対象にしない。
- 再開は既存のADMIN権限とTOTP有効化の保護下で、管理者だけが理由を記録して明示的に行う。自動再開しない。
- 再開後も停止中に失敗したOCRジョブを自動再投入しない。画像が残っている対象だけ、
  利用者の明示的な再実行で再投入する。

### 有効化の前提

- 現在のFree Tier運用では、この予算停止機能を未有効のままにする。
- Paid Tierへ切り替える前に、既存のADMIN管理画面から管理者が月額予算、しきい値、通知先を設定し、
  予算停止機能を明示的に有効化する。
- 有効化済みの状態で設定・集計値・停止状態のいずれかを取得できない場合は、外部AIを停止する。
- 設定未完了のままPaid Tierへ切り替えることを運用手順で禁止する。切替は設定保存、通知試験、
  Google Cloud Billing Budgetの確認を完了した後に行う。

### 権限と設定

- 一般利用者は予算額、全体利用額、通知履歴、停止理由の内部詳細を閲覧・変更できない。
- FamilyGroup内の通常のADMINは、全体予算の閲覧・変更、通知先変更、AI再開を行えない。
  これらは専用の全体AI予算管理者権限だけに許可する。
- 全体AI予算管理者の操作は既存のTOTP有効化必須の管理画面で保護し、変更前後、操作者、時刻、
  理由を監査する。操作ごとの直前TOTP再入力は今回は導入しない。
- 全体AI予算管理者は複数登録できる。初回の登録だけはデプロイ時の明示的な運用手順で行い、
  通常のUI・APIからは行わない。初回登録後の追加・削除は全体AI予算管理者だけが行う。
- 全体AI予算管理者が0名になる削除は拒否し、常に少なくとも1名を保持する。
- 専用権限を持つ利用者も、既存のADMINかつTOTP有効化済みでなければ全体予算操作を実行できない。
- Discord Webhook、SMTPユーザー名、SMTPアプリパスワード、送信元アドレスはDB設定ではなく
  環境変数・デプロイ時の秘密情報で管理する。メール送信はSMTPアダプタとして実装し、初期の
  運用候補は専用GmailアカウントのTLS + アプリパスワードとする。

### 単価・モデルの定期確認

- Geminiの料金・Free Tierクォータを外部サイトから自動取得・自動反映しない。公式料金表と
  AI Studioの実際のレート制限を、全体AI予算管理者が毎月確認する。
- モデルIDを変更する場合は、デプロイ前に料金、Free Tier利用可否、実際のクォータを再確認する。
  単価の更新は管理者が承認し、モデル・用途別の円建て単価、適用開始日、公式参照URL、確認日時、
  確認者を履歴として保存する。
- 単価改定は更新・削除ではなく追記専用とし、各OCRログと商品分類AI実行ログには、呼出し時に
  適用した単価改定IDだけを保存する。これにより後から単価を追加しても過去の推定額を再現できる。
  単価改定IDの参照用Indexは初期には追加せず、集計の実測で必要と判明した場合だけ追加する。
- 実装前から存在する利用ログには単価改定IDを推測で補完しない。単価IDがない既存ログはPaid Tierの
  予算判定から除外し、Paid Tierを有効化した後の新規呼出しだけに単価改定IDを必須で付与する。
- Paid Tierで予算停止機能が有効な場合、現在のモデルに有効な単価がないときの外部AI停止は必須とする。
  月次確認期限の超過は管理者への繰り返し通知だけとし、Gemini利用を停止しない。Free Tierでは固定
  クォータをアプリ設定に持ち込まず、実行時の上限エラーと既存の手動再実行フローを利用する。

## 結果

- 実装は以下へ分割する。
  - [#644 Issue #124](https://github.com/yama180sx/receipt-ai-app/issues/644): 全体設定、停止判定、監査、OCR／分類への適用
  - [#645 Issue #125](https://github.com/yama180sx/receipt-ai-app/issues/645): 管理設定、Discord／メール通知
  - [#646 Issue #126](https://github.com/yama180sx/receipt-ai-app/issues/646): 全体推定額の集計・単価履歴・管理表示
  - [#647 Issue #127](https://github.com/yama180sx/receipt-ai-app/issues/647): モデル・単価・Free Tier確認の定期レビュー
- アプリ側は推定額を防御線として扱うため、請求額との乖離による超過を完全には防げない。
  Paid Tierの実運用ではGoogle Cloud Billing Budgetも必須とする。
- UI上の手動入力画面は本ADRの実装対象に含めない。必要な隠し導線の手動入力は
  [#643 Issue #123](https://github.com/yama180sx/receipt-ai-app/issues/643)で扱う。
