# Issue #132-7: T320 stableからKAGOYAへの選択移行runbook

## 目的

将来の家族向け本番環境であるKAGOYAへ、ログインと基本設定の受入に必要な最小データだけを移行する。対象は世帯、利用者、カテゴリ、店舗、プロンプト、送金履歴である。レシート、画像、解析ジョブ、キュー、利用量、TOTP秘密値、環境固有の認証情報は移行しない。

T320 stableとKAGOYAの間の転送には、管理者が既に承認したSSH経路だけを使う。接続先、鍵、認証情報、実データ、作業ファイルの内容は、Git、Issue、PR、会話、端末履歴へ記録しない。

## 実行主体と境界

- exportはT320 stableのroot管理helperだけが実行する。
- importはKAGOYAのroot管理helperだけが実行する。
- helperは固定した環境名・管理ディレクトリ・確認語だけを受け取り、任意のDB接続先、任意パス、任意コンテナ名を受け取らない。
- 移行文書はroot所有・mode `0600` の新規一時ファイルにだけ作成する。既存ファイルを上書きしない。
- SSH転送後、sourceとtargetのファイル所有者・mode・完全性を値を出さずに検証する。
- importは対象KAGOYA DBの全対象テーブルが空でなければ中止する。dry-runを成功させてから1回だけ実行する。
- importはTOTP秘密値を読まず、全利用者のTOTPを無効として作成する。

## 開始条件

1. T320 stableとKAGOYAの直近root管理backupが成功している。
2. KAGOYAの対象DBが空であることを、値なし件数検査で確認している。
3. 管理者がSSH経路、作業時間、作業担当者、失敗時の停止判断を承認している。
4. KAGOYAのGemini認証・解析受入は本移行の後続Issueとして扱い、移行時には認証情報を更新しない。

## 実施順序

1. T320 stableで値なしのexport事前検査を行う。失敗時はexportしない。
2. root管理helperが一時移行文書を作成し、件数だけを記録する。
3. 管理者が承認済みSSH経路で一時文書をKAGOYAのroot専用一時領域へ転送する。転送先に既存文書があれば中止する。
4. KAGOYAで値なしのtarget空判定とimport dry-runを行う。
5. dry-run成功時だけ、root管理helperでimportを1回実行する。
6. KAGOYAで件数、TOTP無効、Webログインを値なしで確認する。
7. 成功後に限り、両環境の一時文書をroot管理helperで削除する。失敗時は削除せず、原因分類と作業時刻だけを記録して停止する。

## 停止条件

- backup、SSH完全性検査、target空判定、dry-run、import、TOTP無効、ログインのいずれかが失敗する。
- 一時文書の所有者・modeが想定と異なる、または値露出の疑いがある。
- KAGOYAに対象データが既に存在する。

停止時は再実行、DB直接更新、seed実行、TOTP有効化、KAGOYAへの主系切替を行わない。新しい判断を記録してから再開する。

## 受入記録

記録するのは実施日時、環境、`pass` / `fail`、件数、失敗分類だけとする。利用者名、招待コード、パスワードハッシュ、プロンプト本文、接続先、鍵、移行文書の内容は記録しない。
