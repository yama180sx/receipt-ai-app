# 設計・実装規約

## 目的

RecAIptで共通して守る実装上の規約を定める。機能仕様は `docs/features/`、実装済み挙動は `docs/design/`、設計判断は `docs/adr/` を参照する。

## 共通原則

- 変更前に関連するAs-built資料、OpenAPI、Prismaスキーマ、テストを確認する。
- 公開APIは OpenAPI first とし、契約変更は `docs/openapi/openapi.yaml` を先に更新する。
- テナントデータは `familyGroupId` で分離し、Repositoryでスコープを適用する。
- コントローラはHTTP入出力、Serviceは業務規則、RepositoryはPrismaアクセスを担当する。
- 外部サービスの出力は型・候補・権限を検証し、失敗時にデータ整合性を壊さない。

## 変更時の確認

| 変更 | 必須確認 |
|---|---|
| API | OpenAPI、DTO、Mapper、FE生成型、結合テスト |
| DB | Prisma、migration、seed、テナント分離、復旧手順 |
| AI | 入出力スキーマ、費用、失敗時の状態、モック |
| UI | Web/モバイル、エラー表示、手動回帰チェック |
| 設計例外 | ADR、関連仕様、PR説明 |

## 文書ルール

- 正式資料は用途別ディレクトリへ配置し、`_確定版`、`_レビュー反映版`などの重複接尾辞は使わない。
- 履歴資料・監査ログは正本として扱わないことをREADMEに明記する。
- 重要な仕様変更は機能仕様とADRを同じPRで整合させる。
