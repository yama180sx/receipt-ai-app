# アーキテクチャ構成・依存方向

## Backend

```text
HTTP Controller → Service → Repository → Prisma
                     ↓
                  Mapper → API DTO
```

- Controllerは`req`/`res`の処理、Service呼び出し、Mapper・成功envelopeを担当する。
- Serviceは業務規則、トランザクション、Repositoryの編成を担当する。
- RepositoryはDBアクセスとテナントスコープを担当する。
- ControllerからPrismaを直接利用しない。ServiceからHTTPを参照しない。

## Frontend

```text
Screen → feature hook/component → API client → OpenAPI DTO
                                    ↓
                                ViewModel mapper
```

- Screenは薄い画面ラッパーに保ち、状態・API呼び出しはfeatureへ置く。
- API DTOと画面用ViewModelを混同しない。

## 横断ルール

- OpenAPIは公開契約の正本である。
- `familyGroupId`を持つデータは全検索・更新・削除で世帯境界を検証する。
- AI分類は画像OCRと分離し、未解決のテキスト明細だけを候補制約付きで扱う。
- 新しい重要な依存・例外・廃止はADRで理由を残す。

詳細なAs-built構成は [architecture.md](../design/architecture.md) を参照する。
