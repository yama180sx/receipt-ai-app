# 商品単位AI自動分類 — 初期分類範囲・AI入出力・ユーザー修正要件

対象 Issue: [#539 Issue #107](https://github.com/yama180sx/receipt-ai-app/issues/539)

## 1. 初期範囲

### 1.1 標準カテゴリ

全支出に対応する標準カテゴリを用意する。

```text
食費 / 日用品 / 住居 / 水道光熱費 / 交通・通信 / 医療・健康
教育・教養 / 娯楽 / 衣服・美容 / 交際費 / 特別支出 / その他
```

食費には「お菓子」「インスタント食品」「乳製品」「飲料」、日用品には「洗濯用品」「紙製品」の中間カテゴリを初期作成する。他カテゴリは必要になるまで親カテゴリのみとする。

### 1.2 ProductType

初期対象は次の21種とする。

| 親カテゴリ | ProductType |
|---|---|
| 食費 > お菓子 | ポテトチップス、その他スナック菓子、チョコレート、クッキー・ビスケット、せんべい・米菓、アイス |
| 食費 > インスタント食品 | カップ麺、袋麺、レトルト食品、冷凍食品 |
| 食費 > 乳製品 | 牛乳 |
| 食費 > 飲料 | お茶、炭酸飲料、コーヒー、その他飲料 |
| 日用品 > 洗濯用品 | 洗濯洗剤、柔軟剤、漂白剤 |
| 日用品 > 紙製品 | ティッシュ、トイレットペーパー、キッチンペーパー |

メーカー、ブランド、味、容量、個別SKUは、完全一致の標準辞書にレビュー済みのOCR名として登録する場合を除き、初期対象外とする。

標準辞書の追加は以後に登録・更新する明細へ適用する。既存明細を遡って再分類する機能は本範囲に含めない。

## 2. 対象外・範囲外の扱い

- 商品種別を扱わないカテゴリは `not_applicable` とし、AIへ送らない。
- 対象カテゴリに属するが初期の種別にない商品は `outside_initial_scope` とする。Categoryは保存する。
- 候補があるが確定できない商品は `needs_review`、候補がない商品は `unclassified` とする。
- 未分類・要確認でもレシートの登録は止めない。

## 3. AI分類要件（Phase 4）

1. OCR画像解析とは別の分類AIとして実装する。
2. 未解決の明細だけをテキストでバッチ送信する。
3. 返答は明細ID、候補内 `productTypeId` または `null`、`high` / `medium` / `low` とする。
4. AIは候補外の種別、カテゴリ、自由文の分類名を生成できない。
5. 候補外ID、形式不正、`null`は自動確定しない。
6. AIの失敗時も保存フローを停止せず、要確認または未分類を保存する。

## 4. ユーザー修正要件（Phase 2）

ユーザーが商品種別を修正する際、適用範囲を選択できるようにする。

| 選択肢 | 効果 |
|---|---|
| この明細だけ | 明細を修正し、監査履歴のみ残す |
| 同じOCR商品名にも適用 | 世帯別完全一致辞書に登録する |
| 同じ分類用名称にも適用 | 世帯別別名辞書に登録する |

初期選択は「この明細だけ」とする。誤修正の広域適用を避けるため、類似商品全体への自動適用は行わない。

## 5. UI要件

- レシート確認画面ではCategoryとProductTypeを区別して表示・編集する。
- 要確認・未分類・初期範囲外の状態を識別できる。
- Phase 2では修正時の適用範囲を選択できる。
- Phase 5では未確認明細を一覧・絞り込み・まとめて確認できる。
- 統計は未確定商品種別を特定種別へ含めず、明示的に未分類／要確認として扱う。
