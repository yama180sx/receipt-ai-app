## 1. 暫定分析の目的

予備評価の結果を用いて、辞書改善、ProductType追加、初期分類範囲の拡大、類似検索の閾値、AI自動確定基準を評価するために不足しているデータを特定する。
本記録は最終的な次期改善判断ではない。未合意のアプリケーション実装・標準辞書変更・閾値変更は行わず、Issue #565は再評価までopenのままとする。

## 3. 暫定判断

| 論点 | 判断 | 根拠 |
|---|---|---|
| 世帯辞書・別名の仕組み | 最終判断を保留 | 手動登録・監査・無効化は確認できたが、再利用率を測定できていない |
| 標準辞書の追加・変更 | 最終判断を保留 | 未分類11件の個別原因と複数店舗での再現性が未確認 |
| ProductType追加 | 最終判断を保留 | ガソリン等は現行の初期対象外であり、対象範囲拡大の根拠が不足している |
| 初期分類範囲の拡大 | 最終判断を保留 | 食費・日用品以外の運用価値・誤分類リスク・必要なProductType体系を評価していない |
| 類似検索の閾値変更 | 最終判断を保留 | 類似候補・`needs_review`の実データが0件で、閾値比較ができない |
| AI自動確定基準の変更 | 最終判断を保留 | AI実行が0件で、信頼度・修正率・コスト・処理時間を評価できない |

## 4. 継続評価の方針

実レシートを意図的に収集して固定件数へ到達させることは求めない。日常利用で追加データが得られた時点で、予備評価記録へ追記し、改善実装の必要性を再評価する。

追加データでは、次の観点を確認できる範囲で記録する。

1. 食費・日用品の店舗・商品種別の広がり
2. 世帯辞書に登録済みのOCR商品名が再登場した場合の自動再利用
3. `needs_review`またはAI実行が発生した場合の候補・分類結果・コスト・処理時間
4. 未分類明細における、ProductType未定義と辞書・候補不足の区別

上記の事象が未発生であること自体も運用上の観測結果として残す。実レシート評価へ人工的なテストデータを混在させず、動作保証は既存の自動テストで扱う。
