# 商品単位AI自動分類 — 実レシート予備評価記録

対象 Issue: [#564 Issue #114-1](https://github.com/yama180sx/receipt-ai-app/issues/564)  
評価実施日: 2026-07-30（JST）  
評価環境: dev（`develop`、PostgreSQL / Redis / Backend / Frontend 起動済み）

## 1. 目的

実レシートを用いて、現在の初期分類範囲における分類状態、手動修正、世帯辞書学習、AI実行状況の基準値を取得する。
この記録は予備評価であり、ProductTypeの追加、類似検索の閾値変更、AI自動確定基準の変更は行わない。

## 2. 評価条件と手順

### 前提

- dev DBのPrisma migrationが最新であること。
- 商品分類の初期対象は食費・日用品であること。
- 標準辞書はアプリから変更しないこと。

### 手順

1. 実レシートをdev環境へ読み込む。
2. 「商品分類を確認」で明細の状態を確認する。
3. 正しいProductTypeが判断できる明細だけを手動修正する。
4. 同じOCR商品名を今後も再利用したい場合だけ「同じOCR商品名にも適用」を選択する。
5. 「分類学習データを管理」で世帯辞書が有効として保存されたことを確認する。
6. DBの`Receipt`、`Item`、`HouseholdProductDictionary`、`ProductClassificationAiRun`を集計し、以下の定義で指標を記録する。

### 指標定義

| 指標 | 定義 |
|---|---|
| 対象明細数 | `classified`、`unclassified`、`needs_review` の合計 |
| 商品種別未分類率 | `unclassified / 対象明細数` |
| ユーザー修正率 | `classificationSource = manual / 対象明細数` |
| 要確認件数 | `needs_review` の件数 |
| 商品種別対象外件数 | `not_applicable` の件数（商品種別を扱わないカテゴリ、および承認済みの値引き・アプリ適用行） |
| 辞書完全一致率 | `history`、`household_dictionary`、`standard_dictionary` による自動確定数 / 対象明細数 |
| AI呼び出し率 | AI実行対象明細数 / 対象明細数 |
| AI修正率 | AI確定後に手動修正した明細数 / AI確定明細数 |

AI実行が0件の場合、AI修正率・AI処理時間は算出不能として扱う。

## 5. 制約と次期判断への引き継ぎ

- レシート数・商品種別の多様性が小さく、統計的な精度目標は設定できない。
- 同一OCR商品名を含む後続レシートがなく、世帯辞書の再利用率は測定できていない。
- AI実行が0件のため、AI自動確定の閾値、AI修正率、AIコスト・処理時間は評価できていない。
- ガソリン等の初期対象外カテゴリは、今回の評価中にProductTypeを追加しない。対象範囲を拡大するかは、評価結果を分析するIssue #565で判断する。

追加の実レシートを収集する場合は、食費・日用品の異なる商品種別と、既に世帯辞書へ登録したOCR商品名の再登場を含める。これにより、辞書完全一致率とAI関連指標を再測定できる。
