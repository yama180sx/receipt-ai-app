# 商品単位AI自動分類 — 現時点仕様整理

対象 Issue: [#539 Issue #107](https://github.com/yama180sx/receipt-ai-app/issues/539)

## 1. この資料の位置付け

本資料は、商品単位AI自動分類を実装する前に、現行実装と合意済みの目標仕様を比較するための設計資料である。アプリケーションコード、Prismaスキーマ、既存データは本 Issue では変更しない。

実装は本資料を前提に Phase 1 以降の別 Issue で行う。文書体系全体の配置・ADR・共通規約は Issue #108 で整備する。

## 2. 現行仕様（as-built）

現行の画像解析とカテゴリ推定は次の順で動く。

```text
Gemini でレシート画像を解析
↓
商品名・店舗名を正規化
↓
同一店舗の ProductMaster 一致
↓
同一世帯内・店舗を問わない ProductMaster 一致
↓
Category.keywords の部分一致
↓
「その他」カテゴリ、なければ 0
```

- `Category` は世帯別の平坦な家計簿カテゴリである。
- `ProductMaster` は `name + storeName + familyGroupId` を一意キーとし、`categoryId` を記憶する。
- レシートの確定保存、レシート全体の編集、明細カテゴリの編集は、最終カテゴリを `ProductMaster` へ upsert する。
- Gemini は画像から店舗・日付・明細・金額を抽出する。商品種別分類専用のAI呼び出しはない。

## 3. 現行仕様の制約

1. 同じ商品でも店舗ごとに学習が分かれ、OCR表記揺れを吸収しにくい。
2. `ProductMaster` は家計カテゴリだけを保持し、商品種別、分類元、信頼度、修正履歴を保持できない。
3. 分類不能時に「その他」へ寄るため、未解決の分類を改善対象として追跡しにくい。
4. AI画像解析と分類の責務が明確に分離されていない。
5. 世帯が自由にカテゴリを編集できるため、標準辞書を横断利用する前提を置けない。

## 4. 合意済みの目標仕様

### 4.1 マスタと世帯データ

- 標準 `Category` と `ProductType` はアプリ共通の固定マスタとする。
- `Category` は家計簿の集計軸、`ProductType` は商品種別とする。両者は別概念・別モデルである。
- 標準カテゴリは全支出を扱い、商品種別は食費・日用品から段階的に追加する。
- 世帯固有の学習は、確定履歴、世帯別辞書、別名辞書、修正履歴として保持する。
- 標準辞書は利用者の修正で直接変更せず、Phase 1 ではリポジトリ管理のシードデータとする。

### 4.2 ProductMaster と既存データ

- `ProductMaster` は廃止する。
- 現在はテスト運用のため、新モデル導入時に業務データと旧マスタを初期化し、データ移行処理は作らない。
- 管理者アカウントは残す。開発環境で先行検証後、stable 環境を初期化する。

### 4.3 分類の状態

`Category` の確定と `ProductType` の確定は独立して扱う。

| 例 | Category | ProductType | 商品種別状態 |
|---|---|---|---|
| ポテトチップス | 食費 > お菓子 | ポテトチップス | `classified` |
| しょうゆ | 食費 | null | `outside_initial_scope` |
| 判読不能な食品 | 食費 | null | `needs_review` |
| 電気代 | 水道光熱費 | null | `not_applicable` |

商品種別が未設定でも、家計カテゴリが確定していればレシートは保存・集計できる。

## 5. 初期標準カテゴリ

```text
食費
├─ お菓子
├─ インスタント食品
├─ 乳製品
└─ 飲料

日用品
├─ 洗濯用品
└─ 紙製品

住居 / 水道光熱費 / 交通・通信 / 医療・健康 / 教育・教養
娯楽 / 衣服・美容 / 交際費 / 特別支出 / その他
```

初期の `ProductType` は、ポテトチップス、その他スナック菓子、チョコレート、クッキー・ビスケット、せんべい・米菓、アイス、カップ麺、袋麺、レトルト食品、冷凍食品、牛乳、お茶、炭酸飲料、コーヒー、その他飲料、洗濯洗剤、柔軟剤、漂白剤、ティッシュ、トイレットペーパー、キッチンペーパーとする。

## 6. 現行からの主な差分

| 観点 | 現行 | 目標 |
|---|---|---|
| カテゴリ | 世帯別・平坦 | 共通標準・階層 |
| 商品学習 | `ProductMaster` | 確定履歴・世帯別辞書・別名辞書 |
| 分類結果 | `categoryId` のみ | Category、ProductType、状態、分類元、信頼度 |
| 未判定 | その他または 0 | 未分類・要確認・初期範囲外を明示 |
| AI | OCR画像解析のみ | OCR とテキスト分類を分離 |
| 標準辞書 | なし | シードデータで一元管理 |

## 7. Phase 1 の範囲

Phase 1 は、固定標準マスタ、新データモデル、データ初期化、完全一致分類、分類メタデータの保存までとする。類似検索、分類AI、専用確認UI、商品種別統計、標準辞書の管理UIは後続フェーズで扱う。
