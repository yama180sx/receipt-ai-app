# 商品単位AI自動分類 — データモデル・学習辞書・既存データ移行方針

対象 Issue: [#539 Issue #107](https://github.com/yama180sx/receipt-ai-app/issues/539)

## 1. 方針

現行の `ProductMaster` は廃止する。新設する標準マスタと世帯別学習データで、分類結果の根拠と再利用範囲を分離して保持する。

既存データはテスト運用のデータであるため、新モデルへの変換は行わない。導入時はバックアップ後に業務データ・旧マスタを初期化し、標準マスタをシードして再登録する。

## 2. 概念モデル

```text
StandardCategory (共通・階層)
  └─ ProductType (共通・標準カテゴリに属する商品種別)

HouseholdProductDictionary (世帯別の完全一致辞書)
ProductClassificationHistory (世帯別の確定履歴)
ProductClassificationAlias (世帯別の別名辞書)
ClassificationCorrection (手動修正の監査履歴)

Item
  ├─ categoryId
  ├─ productTypeId?
  ├─ productTypeStatus
  ├─ classificationSource
  └─ classificationConfidence?
```

## 3. モデル別の責務

| モデル | スコープ | 主な内容 |
|---|---|---|
| `StandardCategory` | 共通 | 名称、親ID、表示順、有効状態 |
| `ProductType` | 共通 | 名称、属する標準カテゴリ、表示順、有効状態 |
| `HouseholdProductDictionary` | 世帯別 | 正規化商品名から `ProductType` への完全一致規則 |
| `ProductClassificationHistory` | 世帯別 | ユーザーが確定した分類の再利用可能な履歴 |
| `ProductClassificationAlias` | 世帯別 | 分類用名称・別名と `ProductType` の対応 |
| `ClassificationCorrection` | 世帯別 | 修正前後、適用範囲、実行者、日時 |
| `Item` 拡張 | 世帯の明細 | カテゴリ、商品種別、状態、分類元、信頼度 |

## 4. 商品種別状態と分類元

### `productTypeStatus`

- `classified`: 商品種別が確定した。
- `needs_review`: 候補はあるが、ユーザー確認または後続AI判定が必要。
- `unclassified`: 候補がなく、判定できない。
- `outside_initial_scope`: 食費・日用品などの対象カテゴリだが、初期商品種別の範囲外。
- `not_applicable`: 商品種別を扱わないカテゴリ（例: 水道光熱費）、または承認済みの明細名パターンに一致する負額の値引き・アプリ適用行。後者もCategory・金額は保持する。

### `classificationSource`

- `history`
- `household_dictionary`
- `standard_dictionary`
- `similarity`
- `ai`
- `manual`

## 5. ユーザー修正と学習

| 適用範囲 | 保存先 | 再利用 |
|---|---|---|
| この明細だけ | `ClassificationCorrection` | しない |
| 同じOCR商品名にも適用 | `HouseholdProductDictionary` | 正規化済みOCR名の完全一致 |
| 同じ分類用名称にも適用 | `ProductClassificationAlias` | 別名・表記揺れを含む世帯内再利用 |

標準辞書は世帯の修正で直接更新しない。標準辞書の初期内容と変更は、Phase 1ではリポジトリのシードデータをレビューして管理する。

## 6. Category の扱い

- 標準カテゴリは固定マスタとし、世帯による追加・削除・名称変更は行わない。
- 世帯固有の事情は、カテゴリではなく別名辞書・確定履歴で扱う。
- `ProductType` が未設定でも `Category` を保存し、家計簿集計を継続する。

## 7. データ初期化

### 対象

管理者アカウントを残し、レシート、明細、按分、API利用ログ、`ProductMaster`、世帯別カテゴリ、店舗、プロンプト設定を初期化する。

### 順序

```text
開発環境をバックアップ
↓
開発環境を初期化し、標準マスタをシード
↓
Phase 1 の検証と再登録
↓
stable 環境をバックアップ
↓
stable 環境を同じ手順で初期化
```

初期化は破壊的操作であるため、実装Issueで対象テーブル、バックアップ先、復元手順、実行承認を明記する。
