# AI予算・停止管理

対象Issue: [#637 Issue #120-1](https://github.com/yama180sx/receipt-ai-app/issues/637)

Gemini APIをPaid Tierで運用する場合に、Googleプロジェクト全体のAI利用を推定し、
予算超過による外部AI呼出しを防御するための**将来機能仕様**である。現行の実装済み挙動は
[AIパイプライン](../../design/ai-pipeline.md)と[運用・障害対応](../../design/operations.md)を正とする。

## 決定事項

設計判断の正本は[ADR-009](../../adr/ADR-009-paid-tier-ai-budget-governance.md)である。

実装順・変更箇所・検証は[実装計画](./02_実装計画.md)を参照する。

| 項目 | 決定 |
| --- | --- |
| 管理単位 | FamilyGroupではなくGoogleプロジェクトに対応するアプリ全体の単一設定 |
| 利用額 | OCRと商品分類AIを合算したアプリ内推定額。Google請求額とは区別する |
| 月額期間 | Google Cloud Budgetに合わせ、米国・カナダ太平洋時間の毎月1日0:00に開始・リセット |
| 権限 | FamilyGroup内の通常ADMINとは分離した、専用の全体AI予算管理者だけが全体設定・表示・再開を操作 |
| 警告／停止 | 50%・80%はAI継続、100%でAI停止。選択済みの通知先へ各しきい値を送信 |
| 停止対象 | 新規OCR、商品分類AIのみ。閲覧、確定保存、手動登録は継続 |
| 集計障害 | 推定額または停止状態が取得不能なら外部AIを停止する |
| 並列実行 | Gemini呼出し前に想定最大額を予約し、確定利用額と未精算予約額の合計で判定。応答後に実額精算 |
| 予約復旧 | 各HTTP試行は最大2分、予約は15分で期限切れ。1分ごとに回収し、元ジョブは自動再実行しない |
| 再開 | 既存のADMIN管理画面（TOTP有効化必須）で理由付きの明示操作。自動再開・自動再投入はしない |
| 通知 | Discord（既定）とメールを複数選択。少なくとも1つ必須。メールはSMTP抽象化 |
| 通知失敗 | 指数バックオフで最大3回再試行し、最終失敗は監査へ記録。配送失敗だけではAIを停止しない |
| 有効化 | Free Tierでは未有効。Paid Tierへの切替前に設定・通知試験・Google Budget確認後に管理者が有効化 |

月次の料金・クォータ確認期限を過ぎた場合は、全体AI予算管理者へ繰り返し通知するだけでGemini利用は
継続する。モデル変更時などに現在のモデルの有効単価が未登録なら、推定額を計算できないためGemini
利用を停止する。

単価改定は追記専用の履歴として持つ。OCRログと商品分類AI実行ログには、呼出し時に適用した単価改定ID
だけを保存する。これは既存ログへの小さな整数列の追加であり、単価改定の行数も少ない。改定IDの参照用
Indexは、集計の実測で必要と判明するまで追加しない。

単価改定にはモデル・用途別の最大入力・最大出力トークンも保持する。予約額は1回の呼出しではなく、
OCRの通信リトライと算術不整合時の自己修復再解析まで含めたジョブ全体の最大額で計算する。

実装前からある利用ログの単価改定IDは推測で補完しない。単価IDがないログはPaid Tierの予算判定から
除外し、Paid Tierを有効化した後の新規呼出しだけに単価改定IDを必須で付与する。

全体AI予算管理者は複数登録できる。初回登録はデプロイ時の明示的な運用手順で行い、初回登録後の
追加・削除は全体AI予算管理者だけに許可する。専用権限だけでは足りず、既存のADMINかつ
TOTP有効化済みであることも必須とする。全体AI予算管理者が0名になる削除は拒否し、常に
少なくとも1名を保持する。

## Paid Tier切替前チェックリスト

次の全項目が完了するまで、Gemini APIをPaid Tierとして運用開始しない。

1. Issue #124〜#126を実装・レビュー・デプロイし、予算停止機能が未有効であることを確認する。
2. 全体AI予算管理者が、専用管理画面から月額予算、50%・80%・100%のしきい値、通知方式、メール送信先を設定する。
3. Discord WebhookおよびSMTPの秘密情報をデプロイ環境に設定し、送信先ごとの試験通知を確認する。
4. Google Cloud Billingの予算と請求管理者への通知を設定し、アプリ内月額予算との違いを運用者が理解する。
5. 現在のモデルの公式料金、Free Tier利用可否、AI Studio上の実際のレート制限を確認し、単価と確認記録を登録する。
6. ステージング相当環境で、警告、停止、再開、集計障害時停止、単価未登録時停止、停止後の手動再実行を検証する。
7. 実運用のGoogleプロジェクトに課金設定を接続する直前に、管理者が予算停止機能を有効化する。

有効化後、設定・集計値・停止状態を取得できない場合は、外部AIを停止する。設定未完了のままPaid Tierへ
切り替えることは禁止する。

## 利用者向けの障害案内

利用者には内部予算額・利用額を表示しない。

- 日次クォータ超過: 次に再実行できる時刻を案内する。
- 予算停止: 再開時刻を約束せず、サービス再開後に再実行するよう案内する。
- 一時的な429／5xx: 既存のリトライ方針に従う。
- 手動入力: 通常導線には置かず、隠し導線の画面を [#643 Issue #123](https://github.com/yama180sx/receipt-ai-app/issues/643) で扱う。
