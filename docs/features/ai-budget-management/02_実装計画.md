## データ設計

具体的なPrisma名は実装時に既存命名へ合わせるが、次の責務を分離する。

| データ | 役割 | 主な制約 |
| --- | --- | --- |
| 全体AI予算管理者 | 全体設定・表示・再開を許可する利用者の集合 | `FamilyMember`参照は一意。初回・復旧登録はデプロイCLI、通常の追加・削除は管理画面。0名への削除を拒否。ADMINかつTOTP有効化必須 |
| 全体予算設定 | 月額予算、しきい値、機能有効化、通知先選択、停止状態 | FamilyGroupに属さない単一設定。Paid Tier有効化時は通知先を1件以上必須 |
| 単価改定 | モデル・用途別の円建て入出力単価、最大トークン、適用開始、確認情報 | 追記専用。公式URL・確認者・確認日時を保存 |
| AI利用予約 | ジョブ単位の想定最大額、期限、精算・解放状態 | DBトランザクションで作成。15分後に回収対象 |
| 予算監査 | 設定・有効化・停止・再開・全体管理者変更の前後値、理由、操作者 | 改ざんしない追記型 |
| 通知配送記録 | 月・しきい値・通知先ごとの配送状態と試行回数 | 同一通知先の重複を防止し、最大3回再試行 |

`ApiUsageLog` と `ProductClassificationAiRun` には、呼出し時の単価改定IDを追加する。既存行は
`null`のままとし、Paid Tier有効化後の新規行だけを予算判定に含める。初期migrationでは改定IDの
参照用Indexを追加しない。#126では初回登録・改定用のデプロイCLIを提供し、専用権限付きのUI/APIは
#124の全体AI予算管理者基盤へ接続してから公開する。

## 処理設計

```text
OCR upload / 商品分類開始
  → 全体設定・単価改定・月次集計を取得
  → 予算状態または集計を取得不能: Geminiを呼ばず停止結果を記録
  → 確定利用額 + 未精算予約額 + 今回の最大予約額をDBトランザクションで判定
  → 予約成功: Gemini呼出し（各試行2分、既存リトライを維持）
  → 応答成功: 実トークン額を単価改定ID付きで記録し、予約を精算
  → 失敗: 予約を解放し、既存失敗・手動再実行フローへ
  → 15分超過予約: 1分周期で回収。元ジョブは自動再投入しない
```

100%に到達した場合、停止対象は新規OCRと商品分類AIだけである。既存レシート閲覧、解析済み結果の
確定保存、手動レシート登録APIは継続する。利用者には金額・内部停止理由を公開しない。

## API・UI

- 公開契約は `docs/openapi/openapi.yaml` を先に更新する。
- 全体予算管理のAPIは通常のFamilyGroup管理APIと別の権限ミドルウェアで保護する。
- 一般利用者には、予算額・推定額・通知履歴・再開操作を返さない。
- 停止時の利用者向け応答は安全な固定エラーコードにし、日次クォータのみ再試行可能時刻を示す。
  予算停止は再開時刻を約束せず、再開後の明示的な再実行を案内する。
- 通知先はDiscord（既定）・メールを複数選択とし、未選択の方式には送らない。予算停止機能を
  有効にするには少なくとも1つ必須とする。

## 検証

1. Prisma migrationで、既存利用ログの単価改定IDが`null`のままであることを確認する。
2. 全体AI予算管理者が0名になる追加・削除を拒否し、通常ADMINと一般利用者を拒否する。
3. OCRと商品分類AIを合算し、太平洋時間の月境界で正しく切り替わることを確認する。
4. 5並列Workerで予約額を含めて停止しきい値を超える呼出しを拒否する。
5. Gemini成功時の実額精算、例外時の解放、2分タイムアウト、15分期限切れの1分回収を確認する。
6. 集計不能・設定取得不能・有効単価未登録時にGemini HTTP呼出しが0回であることを確認する。
7. 50%・80%の警告と100%停止、通知先選択、重複抑止、配送3回再試行を確認する。
8. 停止中も閲覧・確定保存・手動登録APIを利用でき、再開後も失敗ジョブが自動再投入されないことを確認する。
9. Paid Tier切替前チェックリストをステージング相当環境で実施する。

## 運用上の前提

- Google Cloud Billing Budgetは請求管理者側で設定する。アプリ内推定額は請求額の代替ではない。
- 月額期間は米国・カナダ太平洋時間の毎月1日0:00から次月1日0:00までとする。
- 料金・クォータは毎月およびモデル変更前に、全体AI予算管理者が公式料金表・AI Studioで確認する。
  料金・クォータの外部自動取得や単価の自動更新は行わない。
