# レシート AI 診断（Issue #164）

このコマンドは dev の検証用世帯・ユーザーに限って手動実行する。画像を外部 AI に送信するため、本人が使用を許可した画像か架空の画像を使い、個人情報を必要に応じて隠す。利用量は通常の AI 予算・API 利用記録に反映される。stable や実利用者のデータでは実行しない。

## 実行前の準備

- テスト画像を dev backend コンテナ内の一時領域にコピーする。画像や期待値は Git に追加しない。
- 検証対象の世帯とその所属メンバーを使用する。スクリプトはメンバーの世帯所属を確認する。
- 必要なら、同じコンテナ内に期待値 JSON を配置する。指定した項目だけを比較し、明細は順序を区別しない完全一致と、順番どおりの項目別一致をそれぞれ示す。値引きは実際の印字に基づく負の明細で記述し、推測値を正解にしない。

架空の期待値例（実データはこのファイルや Issue に貼らない）:

```json
{
  "storeName": "テスト店舗",
  "purchaseDate": "2026-01-01 12:00",
  "totalAmount": 950,
  "taxAmount": 0,
  "items": [
    { "name": "テスト商品", "price": 1000, "quantity": 1 },
    { "name": "合計値引き", "price": -50, "quantity": 1 }
  ]
}
```

## 実行

`receipt-dev-backend` は例。ファイル名やユーザー ID は使用する dev 環境に合わせる。１〜５試行を指定でき、１試行で算術不整合があれば自動修復の追加呼び出しもある。通信リトライも生じ得るため、試行回数と費用を確認する。

```bash
sudo docker exec \
  -e RECEIPT_DIAGNOSTIC_IMAGE_PATH=/tmp/receipt-diagnostic.jpg \
  -e RECEIPT_DIAGNOSTIC_EXPECTED_PATH=/tmp/receipt-expected.json \
  -e RECEIPT_TEST_FAMILY_GROUP_ID=3 \
  -e RECEIPT_TEST_MEMBER_ID=6 \
  -e RECEIPT_DIAGNOSTIC_RUNS=2 \
  receipt-dev-backend npm run ocr:diagnose
```

期待値ファイルを使わない場合は `RECEIPT_DIAGNOSTIC_EXPECTED_PATH` の行を省略する。出力には各試行の成功・不完全・算術不整合・通信失敗、初回と再解析の差額、負額行数、所要時間、モデル・プロンプト識別情報、利用量と利用可能な単価に基づく概算費用を含む。概算は応答に使用量と登録済み単価がある場合の参考値であり、実際の請求額や通信失敗時の利用量を保証しない。`coreFieldsStable` は２回以上の全試行が成功した場合だけ算出し、一致しても正しさを意味しない。`observedFinalFieldsStable` は算術不整合時も含めて各試行の最後に観測できた値の揺れを項目別に示す。値の欠落や中断があればその項目は `null` であり、項目の安定は試行の成功や正しさを意味しない。

デフォルト出力に店名・日時・明細名・各金額は含めない。ただし計算差額などはレシートに由来する情報なので、共有前に確認する。**自分の端末で実際の抽出値を確認する場合だけ** `-e RECEIPT_DIAGNOSTIC_SHOW_VALUES=1` を追加する。この場合、店名・日時・金額・明細が標準出力に表示されるため、画面・端末ログ・リダイレクト先の取扱いに注意する。スクリプト自体は診断用の詳細をファイルや DB に保存しない。通常の利用量ログとアプリの既存ログは残る。

429・503 などの外部障害、AI予算による停止、その他の想定外エラーでは、残りの試行を実行せず終了する。算術不整合は次の試行へ進み、各初回・再解析を別々に記録する。停止や失敗は成功と区別され、いずれかの試行が成功以外なら集計を表示した後の終了コードを `2` にする。起動前の設定エラーは `1` とする。

## 比較と終了

同じ画像・期待値・試行回数で、モデル ID とプロンプト識別情報を記録して比較する。`GEMINI_RECEIPT_MODEL` の明示指定は別の固定モデルを比較する場合のみ使い、モデルごとの利用条件・コストを事前確認する。

検証用プロンプトのテキストファイルをコンテナ内に用意し、`-e RECEIPT_DIAGNOSTIC_PROMPT_PATH=/tmp/receipt-prompt.txt` を追加すると、その実行だけシステムプロンプトを差し替えられる。DB のテンプレートは変更しない。元のテンプレートの業態別指示と、読み取れない値を推測しない指示は引き続き追加される。結果の `promptSource` が `diagnostic_override` となり、実際に構成したプロンプト全体のハッシュを記録する。テンプレート ID・版は業態別指示の取得元であり、上書き本文の版を意味しない。通常の API 利用ログにはハッシュと取得元 ID・版が記録されるが、上書き本文は記録されない。プロンプトファイルへ個人情報や秘密情報を含めない。

詳細な値や個人情報は Issue に記載しない。

検証後はコンテナや転送元に残した画像・期待値の保管場所を確認し、必要がなくなったものを管理者が削除する。ログ・バックアップ・端末履歴に複製がないとは限らないため、取扱いに注意する。
