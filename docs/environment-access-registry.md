# 環境・接続経路の運用台帳

関連: Issue #132-5。
この文書は、RecAIptの環境を取り違えずに運用するための**非機密**台帳である。実IP、ホスト名、URL、ポート、ユーザー名、password、鍵、TOTP、招待コード、実データは記録しない。

実接続先とcredentialは、アクセスを許可された管理者のパスワードマネージャーだけで管理する。Git、Issue、PR、通常のメモ、画面共有には転記しない。

## 1. 環境ラベル

接続先の機械名ではなく、次の論理ラベルをすべての運用手順・パスワードマネージャー項目に使う。

| 論理ラベル | 役割 | データの扱い | 通常の入口 |
| --- | --- | --- | --- |
| `dev` | 開発・機能確認 | 検証用。stable／主系と混同しない | 開発用Web、Expo、限定管理経路 |
| `stable` | 現在の安定運用 | 利用者データを扱う。変更は承認済み手順だけ | 通常Web、限定管理経路 |
| `vps-candidate` | 主系昇格前のVPS検証 | 検証段階では主系データと混同しない。昇格後に役割を更新する | VPN経由の通常Web・管理経路 |
| `local` | ローカル開発・統合確認 | ローカル専用。主系・stableの代替ではない | ローカル開発手順 |

主系昇格後は、Issue #118-2-3の受入完了と同時にこの表の役割を更新する。以前の役割を残して二重の主系を作らない。

## 2. 接続経路の区別

| 用途 | 正規経路 | 禁止・注意 |
| --- | --- | --- |
| 日常利用 | 対象環境の通常Web | DBクライアントや開発用Expoを日常入口にしない |
| 開発Web／Expo | `dev`、または承認済みのVPN限定検証環境 | 接続先ラベルを確認してから起動する |
| DB参照 | SSHローカルポートフォワード経由の読み取り専用DBユーザー | DBポートをLAN／インターネットへ公開しない |
| DB保守 | Issue #132-3で整備する、読み取り専用と分離した保守経路だけ | アプリ用DBユーザーや読み取り専用ユーザーを流用しない |
| 緊急password再設定 | root限定helper。対象環境を固定して実行する | A5M2、seed、DB直接更新を復旧手段にしない |

## 3. 接続前チェック

接続・デプロイ・A5M2操作の前に、必ず次を確認する。

1. パスワードマネージャーの項目名にある論理ラベル（`dev`、`stable`、`vps-candidate`、`local`）を読む。
2. 操作目的が「日常利用」「参照」「保守」「緊急復旧」のどれかを決める。
3. 目的に対応する正規経路であることを確認する。DB参照は読み取り専用、保守は別承認の経路とする。
4. ターミナル、A5M2接続名、ブラウザの接続先が同じ論理ラベルであることを確認する。
5. password、鍵、TOTP、接続先の実値をコマンド引数、シェル履歴、Git、Issue、PR、チャットへ渡さない。
6. 作業後に不要なSSHトンネル、A5M2接続、端末画面を閉じる。

対象を判断できない場合は操作せず、パスワードマネージャーの安全なメモとこの台帳を確認してから管理担当者へ確認する。

## 4. パスワードマネージャーの命名規約

項目名は次の形式に統一する。

```text
[RecAIpt][<environment>][<purpose>]
```

`<environment>`は §1 の論理ラベル、`<purpose>`は次のいずれかを使う。

| purpose | 用途 |
| --- | --- |
| `ssh` | 管理用SSH接続 |
| `a5m-readonly` | DB参照専用のA5M2接続 |
| `a5m-maintenance` | Issue #132-3で導入予定の保守用DB接続 |
| `app-admin` | アプリの管理者ログイン。DB credentialではない |
| `vpn` | VPN参加・端末設定 |
| `recovery` | password再設定、backup、DRの手順参照 |

安全なメモ欄には、論理ラベル、用途、正規経路、読み取り専用かどうか、最終確認日、関連Issueだけを記録する。値そのもの、実接続先、認証コード、復旧鍵、招待コードは入れない。

## 5. Gitへ入れてよいもの・入れないもの

| 区分 | Gitへ記録 | 例 |
| --- | --- | --- |
| 運用手順・論理名・確認項目 | 可 | root限定helperの責務、`dev`／`stable`の区別 |
| 非機密テンプレート | 可 | `.env.example`、値なしの設定キー |
| 実credential・暗号化credential artifact | 不可 | `*.cred`、秘密鍵、password、token |
| 実接続先・実運用データ | 不可 | IP、ホスト名、URL、ポート、個人データ |

`.cred`は`.gitignore`で除外し、`scripts/security/diagnose-secret-safety.sh`で追跡・ignore状態を確認する。これは誤追加への防御層であり、秘密値を作業ツリーへ置いてよいという意味ではない。値を扱うファイルは最初からroot管理領域またはパスワードマネージャーにだけ置く。

## 6. 定期確認

月1回、または環境の役割・接続経路・credentialを変更した後に、次を確認する。

- この台帳の役割と、パスワードマネージャーの項目名が一致する。
- 廃止済みまたは未使用の接続項目を「使用停止」と明記し、削除判断は別途承認する。
- A5M2の読み取り専用と保守用を混同していない。
- `./scripts/security/diagnose-secret-safety.sh` が成功する。
- 実値がGitの差分、Issue、PR、チャットに含まれていない。
