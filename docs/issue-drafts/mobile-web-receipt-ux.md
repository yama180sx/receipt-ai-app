# Issue起票用メモ: モバイルWeb公開に向けたレシートUX整備

## タイトル

```text
feat(web): モバイルWeb公開に向けたレシート撮影・トリミング・レスポンシブUX整備
```

## 本文

```markdown
## 背景

公開利用者向けの入口はExpo GoではなくWeb版を基本とする。

Expo Goは端末アプリに組み込まれたSDKとプロジェクトSDKの一致を要求するため、App Store / Google Play経由の自動更新で利用者が接続できなくなる可能性がある。Web版ならこの依存を避けられる。

Web版を日常利用の入口にするには、レシート登録のモバイル体験を実機で十分に成立させる必要がある。

## 目的

iPhone SafariおよびAndroid Chromeで、レシート画像の取得から確認・送信までを無理なく行えるWeb UXを整備する。

## 対応内容

- [ ] レシート画像をカメラ撮影または端末内画像から選択できるようにする
- [ ] カメラ権限拒否・非対応・HTTP制約時に、画像選択へ安全にフォールバックする
- [ ] 画像のトリミング、回転、撮り直しをWeb画面内で行えるようにする
- [ ] トリミング結果を既存のアップロード・OCR解析フローへ正しく渡す
- [ ] 小画面で片手操作できるレイアウトへ調整する
- [ ] iPhone Safari / Android Chrome / タブレット / PCの各画面幅で崩れないことを確認する
- [ ] Safariの「ホーム画面に追加」後の起動・画像登録導線を確認する
- [ ] カメラ、画像選択、トリミング、アップロード失敗時のエラー表示と再試行導線を整備する
- [ ] 実機確認結果を回帰チェックリストへ追加する

## 受け入れ条件

- iPhone SafariとAndroid Chromeの両方で、レシート画像を撮影または選択して登録できる
- 利用者が送信前に画像をトリミング・回転・撮り直しできる
- カメラ利用不可でも画像選択で登録を継続できる
- 主要なスマートフォン幅で重要操作が画面外へ隠れず、横スクロールを必要としない
- Web版だけで日常的なレシート登録が完結し、Expo Goを利用者へ求めない

## 非対象

- Expo SDKの更新
- Expo GoのSDK互換性を利用者向けに維持する対応
- ネイティブ専用アプリの配布・App Store / Google Play申請
- T320のOS・Docker構成変更
```
